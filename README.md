# まと治療院 電子カルテ（自作・開発中）

bonbone Answer（2027年4月サービス終了予定）の代わりを自作するプロジェクトの「フェーズ1：電子カルテ」部分。
進捗・決定事項はAddnessゴール本文を正本とする（このファイルは技術的な起動手順のみ）。

- 親ゴール：https://www.addness.com/goals/8b73b436-b4cd-41f8-9ca1-a07e15b2d014
- フェーズ1ゴール：https://www.addness.com/goals/61d8566d-6d87-487a-be8c-0fc32f2358db

## 技術構成

- Python 3 + Flask + SQLite（このMacにNode.js/Homebrewが無いため採用）
- データベース：`karte.db`（このフォルダ内、gitignore不要＝git管理していない）
- 写真：`static/uploads/` に保存

## 起動方法（ローカルで自分だけ確認する場合）

```bash
cd "projects/まと治療院/電子カルテ"
./venv/bin/python app.py
```

起動したら、同じMacのブラウザで `http://127.0.0.1:5001/` を開く。
同じWi-Fiの中のスマホからなら `http://<このMacのIPアドレス>:5001/` でも開ける（例：`http://192.168.40.202:5001/`。IPアドレスはターミナルの起動ログに表示される）。

**注意：今はまだ院内ネットワークの中だけ。外出先から見るには、次の工程でクラウドへの公開（デプロイ）が必要。**

## できること（2026-09-20時点・ローカル動作）

上部メニュー：予約／売上／集計／患者

- **患者**：新規登録・編集・検索（bonbone「初診入力」の項目：住所・携帯・メール・性別・血液型・職業など）
- **問診カルテ**：来院ごとの基本サービス／追加サービス／回数券等／傷病名／主訴1〜3／内容／備考／11回・5回数券利用、写真
- **予約グラフ**（`/reservations`）：日表示、15分刻み、予約ブロック、空き枠タップで予約入力、同時間帯の重複は保存不可
- **予約入力**：患者・日時・予約時間・予約区分・メニュー・売上区分・来院時刻・施術開始時刻・指名・受付メモ。詳細から問診／お会計／次回予約／来院／キャンセル／削除
- **お会計**（`/sales/new`）：商品・数量・単価・値引・売上区分、内税10%（bonboneと同じ四捨五入）と外税（税抜価格＋10%を加算、端数は四捨五入＝bonboneとの一致は未確認）、入金方法（現金・クレジット・電子マネー・商品券・売掛）、お預かり／おつり。入金合計が請求額と合わないと保存できない
- **売上台帳**（`/sales`）：日別、売上タブ（技術計・回数券計・店販計・値引計・内税・売上計）と入金タブ
- **集計**：月間集計（日別）・メニュー別・年間集計（月別）
- **商品マスタ**（`/products`）：商品名・区分（技術／回数券／店販）・税区分・単価。bonbone設定登録の40品目（技術17・回数券3・店販20、2026-09-20時点）を登録済み。単価変更や追加はこの画面から

## まだできないこと

- 外出先・スマホからのアクセス（クラウド公開が必要）、ログイン認証（今は誰でも開ける）
- 予約グラフの週・月表示、お店の予定（休み）、受付可能残数
- 売上台帳の工程・売掛入金タブ、レシート／領収書、入出金入力、回数券の残数管理
- 帳票のうち月間集計(担当)・日次集計・前年同月対比などbonboneの約24種の集計の大半
- bonboneの来院履歴・問診カルテ・会計履歴の移行（サポート経由でシステム会社に「カルテデータ全件の抽出可否」を確認中。回答待ち）

## データの扱い

`karte.db`（患者・予約・会計）と `static/uploads/`（写真）が全データ。バックアップはこの2つをコピーする。

## bonboneの患者データ取り込み（2026-09-20実施済み）

- 手順（サポート案内）：販促アプローチ → 患者抽出 → 特定条件のお客様 → 特定のお客様にアプローチする → 全顧客 →「自店舗で登録されたお客様」にチェック → 抽出する → CSVを作成する → 項目を選んでCSVダウンロード（メールは送らない）
- `import/bonbone_patients.csv`（1,970件・個人情報を含む。cp932）を `import_bonbone.py` で取り込んだ。患者が0件のときだけ動く
- カルテNo.が別人で重複していたものは、登録日の早い方をそのまま、後の人に枝番（例：`17082-2`）を付けた
- 取り込めていない項目：血液型、既婚区分、注意事項、患者メモ、担当、次回予約（CSVに出せない、または対象外）
- `import/` と `backup/` と `karte.db` は個人情報を含む。作業場の外に出さない

## 全カルテ抽出への準備（2026-09-27時点・実データ待ち）

ダイヤ工業へ「来院履歴・問診内容・施術メモ・会計履歴・写真」の全抽出を依頼中（システム会社へ確認中、回答待ち）。
届いたときにすぐ・漏れなく取り込めるよう、スキーマだけ先に準備した。

- `Visit` に `treatment_memo`・`pain_scale`・`disease_category`・`custom_field_1/2` を追加。日々の問診入力フォームには出さず、
  カルテ編集画面の折りたたみ「bonboneの過去データ用の項目」に入っている（既存データがある時だけ開いた状態で表示）
- `Visit.external_id` / `Sale.external_id`：bonbone側の元IDを保存し、同じファイルを2回取り込んでも重複登録しないための仕込み
- `import_bonbone_history.py`：取り込みスクリプトのひな形（未完成）。患者の突合方法（カルテNo.、重複時はフリガナで絞り込み）は決めてあるが、
  実際のファイル形式・列名が分かるまで読み込み処理は書けない
- 実データが届いたら、このスクリプトを実物に合わせて仕上げてから実行する
